# TP-OPERATIONS-HARDENING-001 revision 1

## Outcome

Harden Teamplay's local installation and runtime identity evidence, add an
optional fresh-context advisory audit that remains subordinate to the current
main Lead, and reduce up-front harness pressure without weakening specification,
review, QA, or Gate ownership.

## Requirements

- `OH-01`: The default installer performs a complete non-mutating preflight,
  refuses modified or unsafe installed files, migrates only byte-exact 0.12.2
  files, and exposes a non-mutating `--check` mode.
- `OH-02`: Obsolete Lead and Gate agent files are removed only when their bytes
  match known Teamplay-owned historical templates; unknown files are preserved
  as conflicts.
- `OH-03`: A runtime inspector emits only allowlisted role, model, effort, tier,
  sandbox, permission, parent, and working-directory fields for one exact child
  thread. It fails on missing or inconsistent identity and can require observed
  isolation for advisory review.
- `OH-04`: Optional fresh-context review uses `teamplay-reviewer`,
  `fork_turns: none`, the complete revision-locked specification and actual
  diff, observed read-only isolation, and advisory-only authority. It cannot
  approve, veto, repair, or replace Lead review, QA, or Gate.
- `OH-05`: Critical and explicit independent-audit requests may select the
  fresh advisory lane. Ordinary runs do not create it automatically.
- `OH-06`: The compact Spec Brief presents objective, ownership, interfaces,
  constraints, and verification as its five implementation-facing sections
  while retaining stable requirement anchors, route, authority, acceptance,
  and continuity controls.
- `OH-07`: Core instructions use progressive disclosure: references are read at
  the stage that needs them instead of loading all detailed contracts up front.
- `OH-08`: Bundle, disposable installation, installed-copy, refusal, runtime
  inspector, shell, and diff validation pass without changing model policy.

## Frozen contracts

- Luna max remains the default implementation Coder and Fast remains Luna-only.
- Terra xhigh implementation requires T1 or T2; no percentage is reserved.
- No Teamplay child may use Sol.
- The current main Lead alone owns canonical specification interpretation,
  integrated review, acceptance QA, final Gate, and completion.
- Fresh advisory review is optional and cannot become a completion gate.
- No installer may print or copy credentials, arbitrary rollout payloads, or
  unrelated user files.

## Acceptance

1. A clean disposable Codex home installs and passes `--check` idempotently.
2. An exact 0.12.2 fixture migrates to 0.13.0.
3. Modified, symlinked, stale-obsolete, and preflight-conflict fixtures fail
   without partial destination mutation.
4. Runtime fixtures prove exact identity output, no prompt leakage, missing
   field refusal, conflicting field refusal, and isolation-required refusal.
5. Static validation confirms fresh review is context-clean, spec-first,
   advisory-only, and never Sol or Gate authority.
6. Existing routing, rendering, lifecycle, economics, English/Korean README,
   and installed-byte checks remain green.
